## What
Altitude pacing term. New pure module scripts/altitude.mjs + web/src/race/altitude.ts twin: `altitudeSlowdown({elevationFt, homeElevationFt, acclimationDays})` → fractional pace penalty (0 below 5,000 ft; a cited per-1,000-ft penalty above the athlete's acclimated elevation, reduced by acclimation days on a saturating curve). `projectRace` (web/src/race/pacing.ts) applies a per-segment altitude penalty from the course profile's mean elevation between stations, scaled by a per-slug knob `altitude_pct` (default 100; 0 disables) persisted like fatigue/restraint in useRacePlan.ts. RacePlanner gets the slider; ModelCheck shows the altitude term instead of the v1 "not modeled" caveat.
## Why
The next A-race averages ~10,300 ft; v1 projections ignore altitude entirely.
## Acceptance Criteria
- scripts/altitude.test.mjs pins the curve at known points (sea level, 5,000, 8,000, 12,000 ft; 0, 3, 14 acclimation days) and monotonicity; the .ts twin is imported by the same test via type stripping (see scripts/features.test.mjs).
- projectRace on the MM100 fixture with altitude_pct 100 is slower than with 0 on the high segments only; ETAs monotone; test in scripts/ via a pure projection harness (extract if needed).
- Slider, persisted per slug; ModelCheck paragraph names the model's total added minutes at the goal.
- home_elevation_ft read from profile.physiology (default null → treat as sea level with a visible "set your home elevation" hint); acclimationDays default 0 (bead 02 derives it).
