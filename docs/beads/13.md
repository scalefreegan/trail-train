## What
Intake stage 3: a second headless agent pass, given `race.json`, `build/course.json` metrics, the athlete profile, and the current Strava facts (`computeFacts` load + pacing model), that writes `block.json` (N weekly targets working back from `date`, N chosen from weeks-until-race capped at 24, with deload weeks and a taper), `nutrition.json` (today's shape; `drop_bag_gear` keyed by this race's drop-bag stations; `heat_window` only when `features.heat`; caffeine plan scaled by `cutoff_h`), `coach_notes` (terrain, climate, altitude, key_demands, race_week — prose ≤ 1200 chars each), `links` completion, and `visual.theme_preset` + `accent` suggestion from a fixed preset list. Exposed as `POST /api/race-intake/plan {slug}` with SSE.

## Why
These are the artifacts that made the MM100 build useful and were all hand-authored; the interview scoped them into intake.

## Acceptance Criteria
- Output contract validated: targets monotone through build phases with ≥1 deload every 3-4 weeks and the last two weeks ≤ 50% of peak; `nutrition.json` passes the existing loader validation in `web/src/race/nutrition.ts`; theme preset ∈ the preset list.
- Every generated field carries `provenance.by: "agent"`; the block's first week is the Monday after the current date, never in the past.
- Snapshot test of the prompt for the MM100 folder (no personal values in the fixture: use `config/profile.example.json`).
- Runs after stage 2 or standalone on an existing folder (used later by re-intake).

## Technical Context
- Block shape: `block.json` = today's `state.block`; the MM100 archived block is the worked example to hand the agent as a style reference.
- Nutrition validation: `loadNutrition` in `nutrition.ts`; drop-bag semantics in `DropBagCard.tsx`.

## Constraints
- Same model/env as the coach; one agent call; JSON only.

## Out of Scope
The dialog, activation, theme rendering.
