## What
Per-race visuals: theme presets, token overrides, accent, and hero. Add `web/src/themes/` with five presets (basecamp-default = today's palette, desert, alpine, forest, night) expressed as the CSS custom properties already used in `web/src/index.css`; `race.json.visual.theme_preset` selects one on activation, `visual.overrides` sets individual tokens, `visual.accent` overrides the accent, and `visual.hero` (a file in the folder, served via a `/api/races/:slug/asset/:name` endpoint) renders in `RaceRibbon` behind the profile. Generic mode uses basecamp-default. The intake review screen's preset picker (dialog bead) previews these.

## Why
The interview asked for accent, hero, panel selection, and full theme override, with presets as the guardrail against visual drift.

## Acceptance Criteria
- Every color/font token in `index.css` is defined on `:root` and each preset overrides only those tokens; switching race swaps a `data-theme` attribute and a style block, no re-render of data.
- Contrast: body text vs background ≥ 4.5:1 in every preset (check with a small `node --test` computing WCAG contrast on the preset files).
- Hero: optional; missing file → current elevation-ribbon-only look. Asset endpoint serves only files inside the slug's folder (path traversal rejected, tested).
- Mac app icon and favicon unchanged (they are Basecamp's identity, not the race's).

## Technical Context
- Theme tokens: `web/src/index.css`; ribbon: `RaceRibbon`/`ElevationRibbon` in `App.tsx` ~257-433.
- The `frontend-design` skill is available for the preset palettes; keep the pre-dawn dark identity.

## Constraints
- No CSS-in-JS library; presets are plain CSS variable maps.

## Out of Scope
Light mode; per-panel reordering.
