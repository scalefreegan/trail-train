## What
Intake stage 2: validate and build. After the agent draft exists, run the schema validator, then a GPX/aid-station reconciliation step: for each aid station find the GPX waypoint by exact name, then fuzzy match (normalized, token overlap), then by distance along the track nearest `total_mi`; write the chosen `gpx_wpt` with `provenance.by: "matcher"` and a confidence; anything below a threshold goes to `unresolved[]`. Then run `build-course.mjs --race <slug>` to write `build/course.json`, compute `sun`, snap `lat/lon`, and derive `race_climbs` metrics for any number of climbs. Expose it as `POST /api/race-intake/build {slug}` with SSE progress.

## Why
Waypoint names in organizer GPX files rarely match manual station names; MM100 needed hand-authored `gpx_wpt` values. The build must not throw on a mismatch (today `build-course.mjs` ~224 throws).

## Acceptance Criteria
- `build-course.mjs` no longer throws on a missing waypoint; it reports it and continues with a track-distance snap flagged low-confidence.
- The matcher is a pure function in `scripts/aid-match.mjs` with `node --test` coverage: exact, case/punctuation variants ("Cross Mtn TH" ↔ "Cross Mountain"), and distance fallback.
- For the archived MM100 folder, matching from names alone reproduces the hand-authored `gpx_wpt` for ≥ 13 of 15 stations.
- Sun computation and climbs from the timezone and literal-removal beads are invoked here; `race.json` gets `sun` and per-climb metrics with provenance.
