## What
Introduce the race-folder schema and a single loader that every script and the web client use to find "the race". Adds `scripts/race-config.mjs` with `loadRaceFolder(root, slug)`, `getActiveRace(root)` (reads `config/active-race.json` → `{slug: string|null}`), `listRaces(root)`, and `validateRaceJson(obj)` returning `{ok, errors[]}`. Adds the TypeScript types for race.json to `web/src/race/types.ts` and a client hook `useActiveRace()` in `web/src/data.ts` that fetches `/api/race/active` (served by a new dev-server middleware in `web/vite.config.ts` that returns the active folder's race.json, block.json, plan.json, nutrition.json merged into one payload, or `{active: null}`).

## Why
Every later bead (migration, generic mode, switcher, intake) reads or writes through this loader. Without one entry point the four duplicated race-constant blocks come back.

## Acceptance Criteria
- `races/<slug>/race.json` schema matches PRD §5.1 exactly (field names, `status`, `features`, `elevation`, `timezone`, `coach_notes`, `visual`, `provenance`, `sources`); `schema_version: 1`.
- `validateRaceJson` rejects: missing timezone or non-IANA string (use `Intl.supportedValuesOf('timeZone')`), aid `total_mi` not monotonic, `cutoff_h` not monotonic among non-null values, `status` outside draft|active|archived, more than one active folder across `listRaces`.
- `config/active-race.json` is created as `{ "slug": null }` when absent; never bootstrapped to a race.
- `GET /api/race/active` returns `{active: null}` when the pointer is null and the merged payload otherwise; refuses cross-site requests the same way `/api/settings` does (see the Origin check near the top of `web/vite.config.ts`).
- A `.gitignore` rule ignores `races/*/*.private.json`, `races/*/sources/`, `races/*/build/`.
- Add `"test": "node --test ../scripts"` to `web/package.json` and unit tests `scripts/race-config.test.mjs` covering validation cases above (Node's built-in test runner, no new deps).

## Technical Context
- Existing course shape to mirror: `config/race-course.json` and `web/src/race/types.ts` (`Course`, `CourseAidStation`).
- Existing state loader pattern: `scripts/state.mjs` `loadState` (atomic writes via `writeJsonAtomic` in `scripts/lib.mjs`).
- Existing client fetch hooks: `web/src/race/useRaceData.ts` (`useCourse` etc.) — follow their 404-vs-error semantics.
- Dev middleware pattern: `/api/settings` handler in `web/vite.config.ts` (~line 831).

## Constraints
- No new npm dependencies. Loader must work when `races/` does not exist (returns empty list).
- Do not change how any view renders yet; this bead is schema + plumbing only.

## Out of Scope
Migration of MM100 (tt: migration bead), generic-mode rendering, the switcher UI, intake.
