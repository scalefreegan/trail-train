## What
Move athlete physiology and personal heuristics out of race and code into `config/profile.json`: `physiology.body_kg` (today `nutrition.json.caffeine.body_kg` 79.4), `physiology.long_run_ref_mi` (today `D_REF = 20` in `web/src/race/pacing.ts`), `long_run_name_patterns` (today the regex in `scripts/sync-strava.mjs` ~49). Remove `race_base` from profile (now `races/<slug>/crew.private.json`). Update `config/profile.example.json`, the profile loader `loadProfile` in `scripts/facts.mjs` (~19-28), the `PUT /api/settings` allowlist, and `CoachSettings.tsx` so these are editable in the dialog.

## Why
A race folder must be shareable and re-generatable without carrying the athlete's weight or local trail names; the pacing fit must not silently use a race-specific reference distance.

## Acceptance Criteria
- `nutrition.ts` `CaffeineConfig` no longer has `body_kg`; `planCaffeine` takes it from profile via the plan hook; MM100's archived `nutrition.json` is migrated (remove the key) with a one-line note in the migration.
- `pacing.ts` `fitPacing` takes `dRefMi` from profile with default 20; the restraint window constants `RESTRAINT_FULL_MI`/`RESTRAINT_END_MI` scale with `race.distance_mi` (50/60 of 100 → 50%/60%).
- Profile is served to the client through the existing settings GET; no personal values in git (`profile.json` stays gitignored).
- Tests: `scripts/profile.test.mjs` for loader defaults and pattern compilation (bad regex → warning, not crash).

## Technical Context
- `useRacePlan.ts` builds the caffeine config and calls `fitPacing`; `facts.mjs` `loadProfile`.

## Constraints
- Backward compatible: a profile without `physiology` gets the previous defaults and a console warning.

## Out of Scope
UI redesign of settings; coach prompt content.
