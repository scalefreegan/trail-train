## What
Migrate the Mogollon Monster 100 into `races/mogollon-monster-100-2026/` with `status: "archived"` and split `web/public/state.json` to version 3: `race`, `block`, `plan_blocks` leave state.json and land in the race folder as `race.json`, `block.json`, `plan.json`. Write `result.json` recording the finish (33.27 h elapsed, finished; Strava activity id left null for the results bead to fill). Migration runs from `loadState` in `scripts/state.mjs` on first load of a v2 file, is idempotent, and writes `state.v2.backup.json` beside the file before touching it.

## Why
MM100 is the reference config and the only real-world test of the schema; the coach should be able to cite it as history. state.json must stop carrying race data before generic mode can exist.

## Acceptance Criteria
- Folder contains: `race.json` (from `config/race-course.json` + `DEFAULT_STATE.race` in `scripts/state.mjs`, with `timezone: "America/Phoenix"`, `features` all true, `elevation.max_ft: 7912`, `coach_notes` populated from the prompt literals at `scripts/coach.mjs` lines ~84, 151, 180, 245, 256 and `web/vite.config.ts` ~202), `course.gpx` (moved from `config/mogollon-monster-100.gpx`), `block.json` (from `state.block`, including `original_targets` if present), `plan.json` (from `state.plan_blocks`), `nutrition.json` (moved from `web/public/nutrition.json`), `crew.private.json` (emergency numbers from `race-course.json.crew_info.emergency` + `race_base` from `config/profile.json`), `result.json` per PRD §10 with `finish_h: 33.27`.
- The two aid-station lists (13 in state, 15 in race-course.json) are reconciled to the 15-station list; `race.json.aid_stations` is the only list.
- `config/race-course.json` and `config/mogollon-monster-100.gpx` are deleted; `git mv` preserves history.
- state.json v3 has only `version, last_updated, agent_notes, preferences`; `STATE_VERSION = 3`; `DEFAULT_STATE` has no `race` or `block`.
- `mergeAgentUpdate` writes `plan_blocks` to the active race's `plan.json` (or `config/generic-plan.json` when no race is active) instead of state.json.
- `scripts/backup.mjs` / `restore.mjs` include `races/**/*.private.json`, `races/**/plan.json`, `races/**/result.json`, `config/active-race.json`, `config/goals.json`.
- Tests in `scripts/state.test.mjs`: v2→v3 migration on a fixture, idempotence on re-run, backup file written once.

## Technical Context
- `scripts/state.mjs`: `loadState` (~line 361) already has a v1→v2 migration to extend; `mergeAgentUpdate` (~405).
- `scripts/race-config.mjs` from the schema bead is the writer/reader for the folder.
- `README.md` "Persistent agentic state" section must be updated to the new split.

## Constraints
- Never lose `agent_notes` or `preferences`. Migration must refuse to run (with a clear message) if the backup cannot be written.
- Personal data (phones, address) only in `*.private.json`.

## Out of Scope
Generic-mode goals file, UI changes, Strava activity linkage for the result.
