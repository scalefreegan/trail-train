## What
The race switcher: the short code in the command bar (`CommandBar` in `web/src/App.tsx` ~117-170, currently `{race.short} ops`) becomes a menu listing the active race, drafts, archived races, "No race (generic)", and "New race…". Selecting writes `config/active-race.json` through `POST /api/race/activate {slug|null}` and triggers a full snapshot reload via the existing refresh pulse. Archived races can be selected read-only: views render with an "archived · <date>" banner and the coach rail explains it is coaching toward the current goals, not this race. Add `GET /api/races` (list with status, date, name).

## Why
Switching is the whole point: load MM100 to review, drop back to generic, activate Softie when the draft is ready.

## Acceptance Criteria
- Menu shows every folder under `races/` grouped by status; selecting an archived race sets the pointer to it but the coach facts still use `goals` (the pointer gains a `mode: "view"|"train"` field; `train` only for active races).
- `POST /api/race/activate` validates the slug exists, refuses to set `train` mode on a draft or archived race, applies the same Origin check as `/api/settings`.
- Switching clears race-scoped client state: pacing knobs are per slug already (timezone bead), chat history stays (athlete-level), `view` persists.
- "New race…" opens a placeholder dialog that says intake is not built yet (the intake dialog bead replaces it).
- Keyboard accessible menu (arrow keys, Escape) using the existing `atoms.tsx` components where possible.
- `npm run build` passes; a `node --test` covers the activate endpoint's validation function (extract it to `scripts/race-config.mjs`).

## Technical Context
- Refresh pulse: `RefreshProvider` in `web/src/providers.tsx`.
- Endpoint pattern: `/api/settings` in `web/vite.config.ts`.

## Constraints
- One active race at a time is enforced server-side, not just in the UI.

## Out of Scope
Intake dialog contents, results capture, theme switching (their beads react to the pointer change).
