## What
Add `config/goals.json` (PRD §5.3) and make the scripts side race-optional: `scripts/facts.mjs` `computeFacts` and `scripts/coach.mjs` run with no active race, producing a rolling 12-week block (current week + 11 prior, targets from `config/generic-plan.json` if present, else the goals volume band midpoint) and a `goals` object in facts instead of `race`. Remove the Mogollon fallback constants `RACE`, `BLOCK_START`, `TOTAL_WEEKS`, `BLOCK_TARGETS` from `facts.mjs`.

## Why
The athlete is in post-race recovery with no A-race; the coach must be able to run in that state. It is also the null case every race-aware code path has to handle.

## Acceptance Criteria
- `config/goals.example.json` committed; `config/goals.json` gitignored; bootstrapped from the example on first run with `phase: "maintain"`.
- `facts.race` is `null` and `facts.goals` is populated when the pointer is null; `facts.block` describes the rolling window with `mode: "rolling"`; with a race active `facts.block.mode` is `"race"` and reads the folder's `block.json`.
- `facts.days_until` is null with no race; no code path throws on `race.date` being absent (grep `facts.race.` and `state.race` in `scripts/` and fix every use).
- `coach.mjs` output contract unchanged in shape; `plan_blocks[].wk` indexes the rolling window when no race is active; the prompt's race paragraph is replaced by a goals paragraph (event_class, phase, volume band, notes).
- `CoachSettings.tsx` gains a Goals section editing phase, volume band, notes via `PUT /api/settings` (extend the validated-key allowlist in `web/vite.config.ts` ~line 679).
- Tests: `scripts/facts.test.mjs` computing the rolling window on a fixed "today" with fixture activities; no-race path of `computeFacts` returns without error.
